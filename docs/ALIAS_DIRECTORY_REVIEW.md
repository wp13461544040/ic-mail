# 目录同步与旧创建候选

后台只显示正常的邮箱数量。同步以 Apple 当前成功返回的完整目录为准：导入新地址，清理远端已不存在的本地地址和邮箱池成员。原租约历史保留，仍有效的租约变为 `retired`，地址引用置空，取件、续租、释放和再次提交全部关闭。清理只更新本地，不向 Apple 发删除请求。

发现本地缺项时，如有可用的独立 Apple Account 通道，则额外核对其完整目录；任一成功目录仍存在的地址都保留，并补入当前同步结果。核对失败不会被当作空目录，本次不清理缺失地址。Web 认证失败、只能回退到 Account 目录时，本次仅导入并提示核对未完成；待 Web 恢复后再清理。未配置 Account 通道时，使用经过验证的完整 Web 目录。仅在发生缺项时追加核对，不新增后台轮询。

清理在短事务中按 Pool 锁、账户锁的既有顺序执行，重新核验账户身份和配置版本。读取目录后新增的地址和 24 小时以内尚未确认的候选不清理，以免把正在创建或尚未传播完成的结果误删。不会清理其他主号，也不会以模糊地址匹配移除记录。

已知来自 Apple Account 通道、尚无完成 ID 的候选，若超过 24 小时，创建恢复会先核对本次 iCloud Web 与 Apple Account 两份完整目录。只有两份有效目录均精确缺失原地址，才把候选隔离为“待复核”。此路径不重发原候选的完成请求，后续创建不再被该候选阻塞。

隔离不表示已经收到上游删除回执。若后续同步精确发现该地址已启用且转发到此主号，则恢复原 ID 与原凭据；若完整目录核对仍不存在且已达到清理条件，则清除本地候选及其占用。

较新的候选、已有完成 ID 的候选、目录读取异常、账户归属不符或信息不完整，仍沿原确认流程处理。创建预算、另一通道、Pool 使用及退役状态不因候选隔离而重置。

账户接口 `alias_count` 是清理后的正常数量，不提供目录快照或双数量展示。

同步响应 `summary.removed_count` 表示本次清理数量。`summary.directory_warning` 为 `APPLE_DIRECTORY_RECONCILIATION_PENDING` 时，已导入地址与凭据仍作为成功结果返回，但本次缺项清理未完成；候选恢复暂未完成时可返回 `APPLE_CANDIDATE_REVIEW_PENDING`。`reviewed_count` 表示从目录恢复的旧候选数量。已有退役工单的对应项会事务收口为 `retired`，结果码 `APPLE_DIRECTORY_REMOVED` 表示依据完整目录清理，不表示网关调用了 Apple 删除接口。
