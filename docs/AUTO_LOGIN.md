# 自动保活服务

自动保活是现有会话续期的补充：新通道或旧通道需要重新登录时，由服务提交已保存的 Apple 账户密码，再从指定链接读取新的双重验证码完成登录。它不会延长 Apple 已失效会话本身的寿命。

## 配置

在「添加主号」或「配置收件凭据」中打开「自动保活服务」，填写：

| 配置 | 用途 |
| --- | --- |
| Apple 账户登录密码 | Apple ID 登录使用的原始密码，与 IMAP 收件用的 App 专用密码分别保存 |
| 保活双重验证接码链接 | 返回该账户新双重验证码的公网 HTTP/HTTPS 接口，支持非标准端口 |
| Apple 账户区域 | 国际区或中国大陆，按原有人工登录使用的区域选择 |

默认关闭。开启时三项必须齐全；关闭时可以全部留空。编辑时密码和链接均不回显，留空保留已存值，可分别覆盖。关闭后保留加密配置，方便再次开启。自定义域名邮箱不使用此功能。

仅对开启自动保活且已启用的 iCloud 主号生效。保存配置、会话被明确判定失效或到达已知过期时间时，事件会唤醒对应主号；不再每 30 秒扫描本地账户或向 Apple 探测是否需要重登。429、创建配额、普通网络故障不会作为重新登录的理由。通道正常时只走已有续期流程，不提交密码，也不读取接码服务。停用主号或关闭此开关后停止自动尝试。

**开关仍开启时，手动退出会取消当前自动尝试，同时触发后续自动重新登录。** 如需保持退出，请先关闭自动保活。

## 验证码读取

支持带验证码语义的纯文本，例如 `AppleID 登录验证码:123456`，以及使用 `otp`、`smsCode` 等明确字段的 JSON。普通状态码、订单编号、多组有歧义的数字和 HTML 页面不会作为验证码提交。响应即使标为 `text/html`，正文为上述纯文本仍可读取。

登录前先读取一次旧码作为基线，登录触发双重验证后每 5 秒读取一次，最多 18 次。有可靠接收时间时还校验时间；没有接收时间时，要求验证码与基线不同。接码服务应保留最近验证码，并在收到新码后更新返回值；每个主号须配置其自身的链接。

实际已确认一种提供方返回上述纯文本格式；另一种已提供样本当前连接超时，尚未验证其真实响应结构。通用 JSON 支持以离线用例验证，不代表所有接码提供方都已实测兼容。

接码读取使用公网直连，不走服务代理，不跟随重定向、不携带 Cookie；限制请求时间和响应大小，并在实际连接时校验 DNS 目标。链接中的参数视同凭据，一并加密保存，不在日志或管理响应中返回。

## 状态与恢复

- 新旧通道分别记录状态和退避，一个通道失败不阻止另一个尝试。每个主号同一时间仅一个自动登录工作，不同主号独立运行。
- 验证码未更新、服务暂时异常等情况从约 5～6 分钟后重试，连续失败逐步延长到约 30～31 分钟；Apple 返回更长 `Retry-After` 时优先遵守。重启服务保留重试期限。
- 服务启动时只恢复一次已开启的保活任务；后续使用对应主号的一次性过期/重试定时器。重复事件不会提前或重置持久退避，同一主号执行期间不会叠加工作。
- 密码错误、账户归属不符或需要人工处理的账户操作会暂停对应通道自动尝试，显示「需要检查保活配置」。处理后覆盖保存相关配置，以重置该状态；普通备注编辑不重置退避。
- 人工登录优先；等待接码期间不占用主号操作锁。人工接管、关闭开关、停用主号或覆盖凭据后，旧自动任务不会继续提交验证码或覆盖新会话。
- 页面可查看每个通道的最近尝试、最近成功、下次尝试和稳定状态码。这里的成功表示登录完成，不代表邮件收件或自动创建也已成功。
- 自动登录失败日志记录上游步骤、HTTP 状态及服务码，不记录密码、验证码或响应正文。Apple 返回 HTTP 503 等暂时异常时继续遵守对应通道的退避期限。
- 旧通道校验与令牌恢复后仍返回 HTTP 421 时，目录同步可尝试已经登录的新通道，保留旧会话。限流、超时及其他上游故障不触发这条回退。
- Apple Account 目录可能同时包含 `privaterelay.appleid.com` 的「通过 Apple 登录」中继地址；同步仅跳过该精确域名的有效地址，继续读取 `icloud.com` 隐藏邮箱，不把其他异常记录静默吞掉。

## 密码保存边界

密码和接码链接使用 AES-256-GCM 加密，随机 nonce，密文绑定主号身份及独立用途。数据库中只保存密文；接口只返回是否已配置，不提供读取或导出明文的功能。密码保持原始内容，不去除首尾空格；验证码不持久化。

自动提交密码需要服务运行时解密，因此这里使用可供程序解密的加密存储，单向哈希不能完成代登录。持有服务器权限和主密钥的人仍具备解密条件，不能承诺连服务器所有者也绝对读不出。备份和迁移时应分别妥善保管数据库与 keys 卷；丢失主密钥后需要重新填写凭据。

## 管理接口

原主号 `POST /accounts`、`PUT /accounts/:id` 可附加：

```json
{
  "auto_login": {
    "enabled": true,
    "region": "global",
    "password": "APPLE_LOGIN_PASSWORD",
    "code_url": "https://CODE_PROVIDER/getcode?token=PROVIDER_TOKEN"
  }
}
```

路径均相对于安装的 `<admin-path>/api/v1`。写操作沿用管理员 Session 与 CSRF 校验；未传 `auto_login` 保持旧配置。此对象与主号配置在同一事务保存。

`GET /accounts/:id/auto-login` 只返回开关、区域、两项凭据是否已保存及双通道状态，要求管理员 Session，且返回 `Cache-Control: no-store`。响应没有密码、接码链接、密文或验证码。字段定义见 [OpenAPI](openapi.yaml)。
